# Contributing to cyopt

cyopt is open to contributions. Open an issue at https://github.com/sheride/cyopt/issues
to discuss substantial changes before opening a PR.

## Development setup

```bash
git clone https://github.com/sheride/cyopt.git
cd cyopt
pip install -e ".[dev,docs]"
pytest -q
```

For FRST optimization (`cyopt.frst.FRSTFlipGraphSpace`, etc.) you need [CYTools](https://cy.tools) installed. The recommended environment is the `cytools` conda env documented in CYTools' README; once you're in that env:

```bash
pip install -e ".[frst,dev,docs]"
pytest -q              # 279 passing + 2 documented skips
```

Note: `pip install cyopt[frst]` does NOT auto-install CYTools because CYTools is distributed via conda, not PyPI. The `[frst]` extra simply marks the dependency. CI tests cyopt's core only; the `[frst]` flow is verified manually against the cytools conda env (see "For Maintainers / Releasing" below).

## For Maintainers / Releasing

### Pre-release checklist

- [ ] All Phase plans complete; `pytest -q` green (279 passing, 2 documented skips).
- [ ] `CHANGELOG.md` updated with the new version section dated today.
- [ ] `pyproject.toml` `version` bumped (e.g., `1.1.0` to `1.2.0`).
- [ ] `README.md` clone URL still points to `github.com/sheride/cyopt`.
- [ ] No uncommitted changes; on `main` and synced with `origin/main`.
- [ ] Trusted publisher binding active on both `pypi.org` and `test.pypi.org` (one-time setup; verify in your account, then Publishing).

### Automated path (preferred - uses OIDC)

```bash
git tag v1.X.Y                    # match pyproject.toml version
git push origin v1.X.Y            # triggers .github/workflows/release.yml
```

The workflow runs: test (matrix 3.10/3.11/3.12), then build, then publish-testpypi, then publish-pypi.

After the `publish-testpypi` job completes, manually verify the [Test PyPI page](https://test.pypi.org/project/cyopt/) renders correctly. If it looks wrong, **cancel the workflow run before the `publish-pypi` job starts** - PyPI does not allow re-uploading the same version. If you cancel, fix the issue, bump to `1.X.Ya2` / `1.X.Yrc1`, push a new tag, and retry. Only the final clean tag should match `1.X.Y`.

### Manual fallback (use only if OIDC workflow is broken)

> **PREFER OIDC.** Only use this path if the GitHub Actions workflow is failing for reasons unrelated to your release content. The API token approach uses a long-lived credential that should never be committed to the repository.

```bash
# From your local machine (NOT in CI):
python -m pip install --upgrade build twine
rm -rf dist/ build/ *.egg-info/
python -m build
python -m twine check --strict dist/*

# Test PyPI first:
python -m twine upload --repository testpypi dist/*
# (provide TestPyPI API token from https://test.pypi.org/manage/account/token/ when prompted)

# Verify the rendered Test PyPI page at https://test.pypi.org/project/cyopt/<version>/
# (README markdown, classifiers sidebar, all [project.urls] links).
# If it looks wrong: bump version to <ver>a2/rc1, edit, retry. PyPI does not allow re-uploading the same filename.

# Then production:
python -m twine upload dist/*
# (provide PyPI API token from https://pypi.org/manage/account/token/ when prompted)
```

The API token is generated by the maintainer at upload time and never lands in a repo secret. Revoke the token after publish if you don't expect to need it again (https://pypi.org/manage/account/token/).

### Verifying `[frst]` install (manual, post-publish)

Because CYTools is not on PyPI, the `[frst]` extra cannot be smoke-tested in CI. After publish, in a `cytools` conda env (or any env with CYTools accessible):

```bash
pip install --index-url https://test.pypi.org/simple/ \
            --extra-index-url https://pypi.org/simple/ \
            'cyopt[frst]==1.X.Y'
python -c "from cyopt.frst import FRSTFlipGraphSpace; print('frst extra ok')"
```

Repeat against production PyPI (omit `--index-url`) once production publish completes.
